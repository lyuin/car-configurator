# Car Silhouette Configurator

車の主要寸法を数値で指定すると、形状がわかる程度の簡易な線画（側面・正面・上面）を描く Web アプリ。
iPad から使うことを想定し、GitHub Pages で静的配信している。

**公開URL: https://lyuin.github.io/car-configurator/**

設計の詳細・データモデル・各タスクの決定事項は [docs/PLAN.md](docs/PLAN.md) を参照。

## できること

**寸法から形を描く**
全長・全幅・全高・ホイールベース・フロントオーバーハング・トレッド・最低地上高・タイヤサイズを指定できる。
シルエットは 軽 / ハッチバック / セダン / ワゴン / クーペ / スポーツ / SUV / ミニバン / ピックアップ の9種。

**未指定の項目は自動補完**
シルエット別の典型比率（実車のカタログ値から起こした値）で埋める。推定値はグレー表示。
数値を触るとその項目が `☑ 固定` になり、以降は推定の再計算から外れる。
ホイールベースを固定して全長を動かすと、前後オーバーハングだけが伸びる。

**既存車種から読み込む**
30台のプリセットを内蔵。寸法空間で散らばるように選んでいるので、どの2台も主要寸法のどれかで
50mm 以上違う（Citroën Ami の全長 2410mm から Ford F-150 の 5885mm まで）。
読み込んだ値は `☑ 車種` と表示され、編集した項目だけ `☑ 固定` に変わる。

**3つのビュー**
側面・正面・上面を切り替えられる。3ビューで縮尺を統一しているので、正面図は枠の中で小さく表示され
「幅より遥かに長い」ことがそのまま読める。500mm グリッドと寸法線をトグルで表示できる。

**2台を比較**
「車Bを追加して比較」で2台目が有効になる。並置（側面・上面は上下に積んで前端を揃える、正面は左右）と
重ね（半透明で重ねる）を切り替えられる。重ねる基準点はフロントバンパー / 前輪中心 / 車体中央から選べる。
スペック表には13項目とその差分が `+310` `−245` `±0` の形で並ぶ。

**URL で保存・共有**
状態は URL のハッシュに入るので、リンクを開けば同じ車が再現される。「URLをコピー」ボタンで取得できる。
URL が無いときは前回の状態を復元する。

## 開発

```sh
npm install      # 依存のインストール
npm run dev      # 開発サーバ
npm test         # テスト（1回実行）
npm run test:watch
npm run build    # 型チェック + 本番ビルド
npm run preview  # ビルド結果をローカル配信
```

`npm test` は型チェックを行わない。型エラーは `npm run build` で検出する。CI は両方を実行する。

## デプロイ

`main` に push すると GitHub Actions が `npm ci` → `npm test` → `npm run build` を実行し、
成功した場合のみ GitHub Pages へデプロイする。

`vite.config.ts` の `base` は GitHub Actions 上でのみ `/<リポジトリ名>/` に切り替わる。
リポジトリ名を変更した場合は `vite.config.ts` の `repoName` も合わせて変更する。

`public/manifest.webmanifest` の `start_url` とアイコンのパスは `./` の相対にしている。
Vite はマニフェストの中身を書き換えないため、絶対パスだとサブパス配信で壊れる。

## URL の形式

```
#s1&v=front&d=1&m=sbs&o=axle&act=b&p=mazda-cx-5&a=sil:suv,L:4575,wb:2700&b=sil:sedan,L:4885
```

| キー | 意味 |
|---|---|
| `s1` | スキーマ版。合わなければ既定値に戻す |
| `v` | ビュー（`side` / `front` / `top`） |
| `g` / `d` | グリッド / 寸法線（`1` / `0`） |
| `m` | 比較の表示（`ov` 重ね / `sbs` 並置） |
| `o` | 重ねる基準点（`front` / `axle` / `center`） |
| `act` | 編集中の車（`a` / `b`） |
| `p` / `pb` | 車A / 車B のプリセット ID |
| `a` / `b` | 車A / 車B の寸法 |

車の寸法は短縮キーの `key:value` をカンマ区切りで並べる。

| キー | 項目 | キー | 項目 |
|---|---|---|---|
| `sil` | シルエット | `tf` | フロントトレッド |
| `L` | 全長 | `tr` | リアトレッド |
| `W` | 全幅 | `gc` | 最低地上高 |
| `H` | 全高 | `t` | タイヤ規格表記 |
| `wb` | ホイールベース | `dr` | ドア数 |
| `fo` | フロントオーバーハング | `n` | 名前 |
| `ro` | リアオーバーハング | | |

**明示指定した項目だけを載せる。** 推定値は URL に入らないので URL が短くなり、
比率テーブルを改善したときに既存の共有リンクも新しい推定に追従する。

**壊れた値は捨てる。** 未知のキー・未知のシルエットやビュー・範囲外の数値・解釈できないタイヤ表記は
すべて無視して既定値にする。共有される前提なので、壊れたリンクでも必ず何か表示されることを優先している。

既存の URL を壊さずにキーを追加できる設計なので、2台比較の追加でも版は上げていない。

## プリセット車種の追加

`src/domain/presets.ts` の `PRESETS` に追加する。JSON ではなく TypeScript なので、
型が合わなければビルドで落ちる。

```ts
{
  id: 'toyota-prius',              // kebab-case、一意
  name: 'Toyota Prius',
  silhouette: 'hatch',
  length: 4600,
  width: 1780,
  height: 1430,
  wheelbase: 2750,
  tire: '195/60R17',
  // 推定が明らかに外れる車にのみ指定する（キャブオーバーなど）
  // frontOverhang: 690,
  // シルエットの既定値と違う場合にのみ指定する
  // doors: 3,
}
```

全長の昇順に並べること。トレッドや最低地上高は持たせず自動補完に任せている。

`src/domain/__tests__/presets.test.ts` が選定方針を検証しているので、
既存の車と主要寸法が似すぎている車を追加するとテストが落ちる。これは意図した動作で、
似た大きさの車を並べても比較の役に立たないため。

## 技術構成

| 項目 | 選択 |
|---|---|
| ビルド | Vite |
| UI | React + TypeScript（strict + `exactOptionalPropertyTypes` 等を全有効） |
| テスト | Vitest + Testing Library（jsdom） |
| 描画 | SVG（`viewBox` を mm 単位でとる） |
| 配信 | GitHub Pages（静的、バックエンドなし） |

描画に Canvas ではなく SVG を使っている理由は、寸法線や数値ラベルを DOM として扱えること、
`viewBox` を mm でとれば2台を同一スケールで並べる計算がほぼ不要になること、
オーバーレイの半透明表現が素直なこと、そして後からドラッグ操作を足すときに
ヒットテストを自前実装せずに済むこと。

座標系は x が車の前端バンパーを 0 として後方へ mm、y が地面を 0 として上方向へ負。
y を負にすると SVG のデフォルト（y 下向き）とそのまま噛み合うので、上下反転の変換が不要で、
寸法線の文字も鏡像にならない。
